huashu-mac-use 工作原理agent 操控没有 API 的 macOS 原生 app，并留下可复现的取证

1先探测，再选层

第 0 步 probe.sh <app>
bundle、架构、URL scheme、AppleScript 字典、本地端口、AX 控件数、版本号
↓ 按 app 内核分流
内嵌 Chromium（Electron / CEF）
→ L0 · CDP：mac open --cdp 起调试端口，cdp.js snapshot / find / insert / mouse
零焦点 · 跨 Space · 多 agent 互不干扰
原生 / 自绘
→ L0 自带 CLI、字典、URL scheme
→ L1 · AX 树（探到可编辑控件且实写后状态变化才算通）
→ L2 · 窗口坐标：mac see 看图，图上像素直接给 mac op
↓
L3 · 像素：控制手段的最后一档，验证手段的每一步。截图坐标三种写法内核自己换算，agent 永远不做乘法
经验：同架构两种结果、同一个 app 两个窗口两种结果——不按架构预测，按窗口试一次

2读完全后台，写默认零焦点

读：列窗口 / 截窗口 / AX / CDP
全部后台，不 activate、不切 Space、不动鼠标。被遮挡的窗口照样截得干净
写：mac op 走阶梯
① postToPid 直投进程（不抢焦点）
② 截图差分判生效
③ 判不出才升级借焦点
↓ 升级借焦点前，自动过闸
四道闸（--dry 可预演）
前台是不是目标 · 落点有没有被别的窗口压住 · 用户 2 秒内动过键鼠就等他停手（最多 15 秒） · 全机同时只允许一个进程借焦点
↓
接管时屏幕四角脉冲取景框（HUD）：鼠标穿透、不抢焦点、跨 Space、对截图隐身
借用约 0.5 秒立刻还焦点、还原鼠标，等待与截图都挪到还完之后，并报出实测秒数
跨 Space 是默认拓扑：agent 常在全屏终端里，目标 app 在另一个桌面。读随便读；坐标写操作内核直接拒绝（refused: cross-space），改走 CDP 或请用户挪窗口，不自己切 Space
↻ 每次收工回流

3回读验证，经验进工具

判据阶梯（从弱到强，前三级都骗过人）
1工具返回 success
2读回控件值
3截图看见字
4应用状态指示器：发送键由灰变亮、placeholder 消失
5副作用：任务进列表、文件落盘、请求发出
动作后自动差分，回 effect=confirmed | partial | suspected_noop | unverifiable——suspected_noop 不是失败，是「回去重看」
↓ 学到新东西
先问：这条教训能不能变成工具行为？
能 → 改代码（坐标换算、shot 自诊断、AX 查两次、跨 Space 拒绝…都是这么来的）
不能 → 只进 references：单 app 观察进 app 档案，两个 app 重现才升正文；坐标、端口、界面文案是易腐信息，永远不进正文
